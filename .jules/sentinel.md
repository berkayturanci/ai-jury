## 2024-05-18 - [CRITICAL] Prevented gh CLI stdout/stderr Secret Leakage
**Vulnerability:** Subprocesses (`gh` CLI commands in `_gh` and `_gh_with_input`) could print raw output or errors containing sensitive data (e.g. `ghp_` tokens) directly into raised `RuntimeError` messages, bypassing prompt/JSON context redaction layers.
**Learning:** External dependencies (CLIs) running outside the Python process boundary don't inherit the application's memory protections or logging filters. Their raw `stderr` and `stdout` must be aggressively sanitized before crossing back into application exception/logging flows.
**Prevention:** Apply `ai_jury.redaction.redact()` explicitly to the `.stderr` / `.stdout` / decoded string buffers of failed `subprocess.Popen` and `subprocess.run` calls *before* wrapping them in Python exceptions or returning their strings.

## 2026-06-14 - [CRITICAL] Prevented Exception Strings and Subprocess Success Outputs from Secret Leakage
**Vulnerability:** Subprocesses (`gh` CLI commands in `_gh` and `_gh_with_input` on success) and Python exceptions from generic errors (e.g., spawn failures, URL errors) could leak sensitive data (e.g. `ghp_` tokens) directly into application logs and outputs, bypassing redaction layers that were only applied to errors.
**Learning:** External dependencies (CLIs) running outside the Python process boundary don't inherit the application's memory protections or logging filters. Not only their raw `stderr` and `stdout` of failed calls, but also successful `stdout` and strings generated from arbitrary Python exception errors must be aggressively sanitized before crossing back into application exception/logging flows.
**Prevention:** Apply `ai_jury.redaction.redact()` explicitly to the `.stdout` decoded string buffers of successful `subprocess.run` / `Popen` calls, and to `str(exc)` or `str(exc.reason)` in `except` blocks, *before* returning their strings or embedding them in error models.
