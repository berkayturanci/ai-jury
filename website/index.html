Install once. Run a cross-vendor review jury anywhere.

A small, stdlib-only Python CLI that drives each vendor's native coding-agent CLI — Claude Code, OpenAI Codex, Google Antigravity — plus an optional free, offline local / open-weight model, to review the same diff or PR, cross-examine each other, and synthesize one chair verdict. Local-first. Not API calls.

View on GitHub Try the interactive demo ↓

Why a native-CLI jury

Different models miss different things. Running them as an adversarial panel — each seeing the others' findings and arguing — surfaces more real issues and filters more false positives than any single reviewer. The research-backed lever is vendor heterogeneity, not more rounds — and a free local/open-weight model adds a different perspective at zero marginal cost. Each reviewer runs in its own native CLI with its own tooling, not a raw model API call.

Quickstart

      
pipx install ai-jury

jury init                                      # scaffold jury.toml (detects agents + local models)
jury init --preset offline                     # free, local-only ($0); also: fast / balanced / thorough
jury config show                               # see the effective config that will run
jury --pr 123                                  # review a GitHub PR
jury --pr 123 --post --post-progress           # live: a sticky PR comment updated each round/chunk
jury --pr 123 --post --post-mode phased        # post Round 1 / debate / decision as separate comments
jury --pr 123 --auto                           # auto-depth: scale rounds/verify to the diff
jury --ci --fail-on high,critical              # gate CI on blocking findings
jury --mock --diff-file examples/sample.diff   # offline demo, no live CLIs

      

        Requires Python 3.11+ and at least one reviewer — an agent CLI
        (claude, codex, agy) or a free, offline
        local model via Ollama; missing/unreachable ones are skipped. gh
        is needed for --pr.
      

    


    

      
Configuration

      

        A run is driven by a jury.toml (or built-in defaults). Don't hand-write
        it the first time — scaffold one, inspect what will
        run, then go. Every field is in the
        configuration reference.
      


      

        

          
Set up & inspect

          
jury init                  # interactive scaffold
jury init --preset balanced # or: offline | fast | thorough
jury init --list-agents     # which CLIs are available
jury init --list-models     # local (Ollama) models
jury config show            # the effective resolved config
jury --doctor               # readiness + next steps

        

        

          
A jury.toml

          
[jury]
rounds = 2          # 1 = review only, 2 = + debate
chair  = "claude"   # who synthesizes the verdict
verify = true       # drop false positives
# auto_depth = true # scale depth to the diff (--auto)

[[agent]]
name = "claude"
vendor = "anthropic"
command = "claude"

[[agent]]              # free, offline reviewer
name = "qwen"
vendor = "local"
model = "qwen2.5-coder:7b"
endpoint = "http://localhost:11434/v1"

        

      

      

        CLI flags override the file per run (e.g. --rounds, --verify,
        --auto, --chair). Validate with
        jury --config-validate; --strict-config turns warnings into errors.
      

    


    

      
How it works

      
    
        
  1. Round 1 — independent review. Every available agent reviews the diff concurrently with the same rubric.
    2. 
        
  2. Round 2 — debate (adaptive). Each agent sees the others' reviews and emits agree / dispute / missed; with early_stop a unanimous panel skips it.
    3. 
        
  3. Verification. The chair re-judges each finding to drop false positives — and the report shows the evidence behind each one.
    4. 
        
  4. Synthesis. The chair consolidates into one verdict plus consensus, disputed, and single-reviewer findings.
    5. 
      

      

        Large diffs are filtered + chunked; runs are bounded by an optional budget with
        retries; results can be cached; and a review can be incremental (only what changed
        since the last run).
      

    


    

      

        
Free & offline option

        
Add a local open-weight model (Ollama, llama.cpp, vLLM, LM Studio) as a panel seat — zero cloud cost, fully offline, or mixed with cloud CLIs for more diversity. Local reviewer →

      

      

        
Follow the run live

        
--post-progress keeps a sticky PR comment updated each round/chunk; --post-mode phased posts Round 1 / debate / decision as separate comments. Cookbook →

      

      

        
Secure by default

        
Reviewers read attacker-controlled diffs, so they run sandboxed/read-only (Codex -s read-only, Antigravity --sandbox, Claude tool denylist). diff-only context + secret redaction on. Security & data-flow →

      

      

        
Cost-aware

        
--auto scales rounds/verify to the diff (docs-only → shallow; security-touching → full); large diffs are chunked; results cached. Configuration →

      

      

        
CI citizen

        
--ci --fail-on gates merges; --format json|sarif for code scanning; inline + summary PR comments; opt-in classification labels.

      

      

        
Drop-in skill

        
Install as a Claude Code plugin or copy the skill into .claude/skills/. Platform support →

      

    


    

      
Not a hosted SaaS. This is a local-first CLI + skill, not a hosted review service or a general multi-agent framework. It reviews and reports; it can emit inspectable suggested patches for verified findings, but never applies them automatically.
